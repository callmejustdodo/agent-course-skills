# 업무 스킬 생성·검증

## 생성 범위

현재 설치된 스킬의 실제 기능과 권한으로 단계들을 처리할 수 있는지 먼저 확인한다. 같은 절차를 기존 스킬에 입력만 바꿔 재사용할 수 있으면 새 스킬을 만들지 않는다.

새 스킬이 필요하면 다음을 한 묶음으로 제안한다.

- 스킬 이름과 반복 가능한 결과
- 포함하는 `Wxx-Sxx` 단계 ID와 제외할 사람 단계
- 입력·출력, 시작 조건, 필수 승인
- 재사용할 툴·스킬과 아직 미확인인 연결·권한

사용자와 묶음의 경계를 합의한다. 결과를 바꾸는 미확인 사실은 한 번에 하나씩 묻는다. 모든 단계를 하나의 거대 스킬로 만들거나 단계마다 스킬 하나를 만들지 않는다.

## 파일 작성

합의 후 추가 생성 요청을 기다리지 않는다. 읽을 수 있으면 현재 환경의 공식 `skill-creator` 지침을 따른다. 소문자·숫자·하이픈 이름을 사용하고 정본을 다음 위치에 작성한다.

```text
company-agent/skills/<name>/SKILL.md
company-agent/skills/<name>/references/   # 실제로 필요할 때만
```

이 경로는 설계 산출물 보관 위치이며 앱의 자동 발견 위치라고 가정하지 않는다. 현재 앱의 공식 프로젝트 범위 스킬 위치를 확인할 수 있고 현재 작업공간 안이라면, 같은 내용의 실제 발견 가능한 스킬도 그 위치에 생성한다. 이 파일 생성은 이미 합의한 업무 스킬 작성 범위이므로 다시 허락을 묻지 않는다. 사용자 프로필·전역 스킬 위치로 복사하거나 앱 설정을 바꾸는 일은 별도 설치다.

같은 목적의 폴더가 이미 있으면 사용자 내용과 기존 결정을 보존해 갱신한다. 충돌하는 새 이름을 임의로 만들지 않는다. SKILL.md에는 다음을 포함한다.

- 언제 사용하는지 구분되는 `name`과 `description`
- 담당 단계 ID와 완료 결과
- 필요한 입력, 없는 입력을 다루는 방식, 사람 승인 경계
- 재사용할 툴·스킬과 실제 권한 확인
- 정상 흐름, 대표 예외, 중단·재개와 결과 검증
- 비밀값 대신 입력 이름이나 자리표시자

녹화가 있어도 화면 좌표와 시연 당시 값을 그대로 복제하지 않는다. 안정적인 커넥터·API·CLI·MCP가 있으면 이를 우선하고, UI 조작이 필요한 경우 앱·창·컨트롤처럼 안정적인 대상을 기술한다.

## 설치와 검증

정본 생성, 프로젝트 발견 경로 생성, 사용자 프로필 설치를 구분한다. 공식 프로젝트 스킬 위치가 확인되면 충돌을 검사하고 발견 가능한 파일까지 만들되, 별도 요청 없이 사용자 프로필·전역 설치 위치로 복사하거나 기존 설치본을 덮어쓰지 않는다.

각 생성 스킬을 다음 순서로 검증한다.

1. 파일 생성 여부를 확인한다.
2. 가능하면 공식 구조 검사기를 실행한다. 없으면 frontmatter, 폴더명, 내부 링크, 미완성 자리표시자를 검사한다.
3. 개인·회사 정보를 제거한 입력으로 정상 사례를 모의 실행한다.
4. 필수 정보가 없는 사례에서 질문·중단·안전한 결과가 나오는지 확인한다.
5. 가장 흔한 예외 하나에서 재시도·사람 전달·중단 기준을 확인한다.
6. 발견 경로를 만들었다면 앱이 스킬로 인식하는지 확인한다.
7. 실제 업무 계정·툴 실행은 별도 상태로 둔다.

각 결과를 `통과 / 실패 / 미수행`과 근거로 기록하고 실패하면 파일을 고친 뒤 다시 검사한다. 생성 스킬과 담당 단계 ID, 정본·발견 경로·전역 설치 상태, 구조·모의·앱 인식·실제 업무 검증 상태를 `agent-design-decisions.md`와 `skill-verification.md`에 남기고 `workflow-design-state.md`의 다음 질문과 파일럿을 갱신한다.
