# 기록 형식과 완료 조건

현재 작업공간의 `company-agent/`를 사용한다. 기존 문서가 있으면 관련 사실을 읽되 삭제하거나 초기화하지 않는다. 아래 파일이 이미 있으면 해당 섹션만 갱신한다.

파일 도구를 사용할 수 없으면 저장했다고 말하지 않는다. 같은 구조의 초안을 대화에 유지하고 `파일 저장 불가`로 표시한 뒤, 도구가 생기면 기존 기록과 병합한다.

## `workflow-map.md`

- 합의한 분석 범위와 아직 보류한 업무 목록
- 업무별 시작·끝, 사용자, 결과와 완료 기준
- 안정적 단계 ID, 순서·분기·반복 관계
- 단계별 트리거·시간·빈도·처리량
- 입력·자료·행동·출력·다음 담당
- 사람 판단·예외·권한·현재 앱과 환경
- `확인 / 추정 / 미확인`과 근거

## `agent-design-decisions.md`

단계별로 다음을 기록한다.

- 처리 방식: 사람 / 업무 조정 / 규칙 / AI 보조 / 에이전트 / 미확인
- 재사용할 현재 툴·스킬 또는 신규 후보
- 툴·스킬·API/CLI/MCP·모델·하네스의 역할
- 프로세스·모델·데이터·채널·트리거의 위치
- 추천 이유, 대안, 비용·위험, 바꿀 조건
- 출처 URL, 확인 날짜, 조사 범위
- `사용자 합의 / 추천 / 보류 / 미확인`
- `조사 / 설치 / 인증 / 기능 실행 / 업무 결과` 확인 상태
- 재사용 또는 생성할 업무 스킬과 담당 단계 ID

## `workflow-design-state.md`

- 현재 분석 중인 업무와 단계
- 전체 업무 범위의 완료·진행·미분석·보류 상태
- 마지막으로 확인된 사실과 사용자 수정
- 다음에 물을 질문 하나
- 막힌 조건과 확인 방법
- 다음 파일럿과 관련 파일

## `skills/<name>/SKILL.md`

- 합의한 반복 업무를 실행하는 실제 스킬
- 담당 단계 ID, 입력·출력, 사람 승인과 예외
- 기존 툴·스킬 재사용과 미확인 권한
- 필요한 경우에만 `references/` 추가

## `skill-verification.md`

- 생성·갱신한 스킬과 담당 단계 ID
- 정본 경로, 프로젝트 발견 경로, 사용자 프로필 설치 상태
- 파일 생성·구조 검사 결과와 검사 방법
- 정상 / 필수 정보 누락 / 대표 예외의 기대·관찰 결과
- `모의 / 앱 인식 / 실제 업무`, `통과 / 실패 / 미수행` 상태와 근거
- 다음 실제 파일럿

## 완료 조건

- 사용자가 합의한 담당 업무 범위가 모두 나열되고, 분석하지 않은 업무가 숨겨지지 않았다.
- 각 분석 대상의 처음부터 끝까지와 사람 단계·예외가 정리됐다.
- 모든 단계가 처리 방식과 연결됐거나 `미확인`과 후속 확인 방법을 갖는다.
- 신규 추천은 출처와 확인 날짜가 있고, 실제 설치·실행 여부와 구분된다.
- 실행 프로세스·모델·데이터·채널·트리거가 혼동 없이 결정되거나 보류됐다.
- 결과에 영향을 주는 중요한 선택은 사용자가 합의했거나 명시적으로 보류했다. 답하지 않은 추천을 결정으로 간주하지 않는다.
- 기존 스킬로 처리되지 않는 합의 범위는 실제 SKILL.md로 생성됐거나, 생성할 수 없는 이유와 후속 질문이 기록됐다.
- 생성 스킬마다 단계 ID가 연결되고 정상·필수 정보 누락·대표 예외가 검증됐다. 실제 툴을 쓰지 않은 결과는 모의 검증으로 구분됐다.
- 정본 생성·프로젝트 발견·사용자 프로필 설치·구조·모의·앱 인식·실제 업무 검증 상태가 구분되고 다음 실제 파일럿이 정해졌다.

마지막 보고에는 전체 문서를 반복하지 않는다. 합의된 설계, 보류·미확인, 다음 파일럿, 파일 링크만 간결하게 보여 준다.
