# `workflow-agent-design` 검토 시나리오

실제 계정·회사 자료를 사용하지 말고 임시 작업공간에서 확인합니다. 기대 결과의 문구가 아니라 대화와 기록의 행동을 검토합니다.

## 1. 업무가 여러 개인 초보 수강생

사용자: “영업팀에서 문의 메일, 상담 일정, 주간 보고를 맡고 있어. 자동화하고 싶어.”

확인:

- 업무 하나를 임의로 전체로 취급하지 않고 세 업무의 범위를 먼저 확인한다.
- 우선 업무를 골라도 나머지를 `미분석·보류`로 기록한다.
- 질문을 한 번에 하나씩 하고, 최근 사례로 시작부터 끝까지 그린다.
- 사람 판단·예외·PC 종료 후 실행 요구를 확인한다.

## 2. 신규 툴 추천이 필요한 업무

사용자: “웹 관리자 화면에서 주문을 내려받아 데스크톱 ERP에 입력해.”

확인:

- API·CLI·MCP 등 현재 연결 가능성을 먼저 조사하고 화면 조작을 기본값으로 단정하지 않는다.
- 공식 문서와 일반화한 검색어를 사용한다.
- 현재 방식과 대안 1~2개, 정확한 출처 URL·확인 날짜를 기록한다.
- 문서 확인과 설치·인증·기능 실행·업무 결과를 별도 상태로 남긴다.
- 규칙 또는 사람 처리 유지가 더 적절하면 이를 제안할 수 있다.

## 3. 기존 기록에서 재개

준비: `company-agent/workflow-map.md`에 `W01-S01`, `W01-S02`와 사용자 수정 내용을 둔다.

사용자: “어제 하던 설계를 계속해 줘.”

확인:

- 기존 파일과 사용자 수정을 먼저 읽고 같은 질문을 반복하지 않는다.
- 기존 단계 ID를 유지한다.
- 진행 상태의 다음 질문 하나부터 재개한다.
- 오래된 추천은 현재 공식 자료로 다시 확인하되, 사용자 합의를 임의로 바꾸지 않는다.

## 2026-11-07 독립 동작 점검

실제 기업이 아닌 가상 사례로 다음 응답을 생성해 확인했다.

| 사례 | 관찰 결과 |
| --- | --- |
| 온라인 주문 관리·거래처 정산 두 업무로 첫 인터뷰 | 두 업무의 범위를 유지하고 다음 질문 하나로 시작 |
| Gmail 문의 → Drive 정책 → 답변 초안 → 관리자 승인 | 공식 문서 조사, 단계별 후보 추천, 설치된 스킬과 실제 계정 연결 상태 구분 |
| 노트북 종료 후 실행 요구 + 회사 PC 전용 ERP + Supabase | 이전 실행 조건을 재검토하고, 데이터 저장과 업무 실행을 분리. 네트워크 없이 API 지원을 미확인으로 표시 |

세 응답 점검은 통과했다. 스킬 구조 검사와 UI 메타데이터 YAML 파싱도 통과했다. 다회차 인터뷰의 상태 파일 유지, 실제 계정 인증·CLI 실행, 설치된 앱의 자동 스킬 선택은 검증하지 않았다. 위 1~3의 전체 회귀 시나리오를 모두 끝까지 실행했다는 뜻은 아니다.
